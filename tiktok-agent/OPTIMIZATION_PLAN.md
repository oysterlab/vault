# TikTok Art Autoresearch — 최적화 에이전트 계획

## 핵심 개념

Karpathy의 autoresearch처럼, AI가 자율적으로 실험하고 성과를 측정하고 접근법을 개선한다.
차이점: autoresearch는 val_bpb 하나를 최적화하지만, 우리는 **3개 레이어**를 동시에 최적화한다.

---

## 3개 최적화 레이어

### Layer 1: 콘텐츠 최적화 (메인 루프)
```
무엇을: 포스트의 스코어 (0-100)
어떻게: 훅, 크롭, 톤, 시퀀스를 변형하며 A/B/C 테스트
피드백: 6시간 후 TikTok 메트릭
사이클: 하루 2회 (06:00, 19:00)
에이전트: Sam → Alex → Maya ↔ Jin
```

| 최적화 변수 | 메트릭 영향 | 실험 방법 |
|------------|-----------|----------|
| 훅 스타일 | completion, shares | A=대조군 vs B=실험 |
| 크롭 좌표 | completion, slides_viewed | 같은 명화, 다른 줌 시퀀스 |
| 텍스트 톤 | shares, saves, comments | 사실나열 vs 대화체 vs 공감 |
| CTA 스타일 | comments, saves | 질문형 vs 태그형 vs 저장형 |
| 슬라이드 수 | completion | 5장 vs 7장 vs 9장 |
| 명화 선택 | 전체 | 밈급 인지도 vs 니치 |

### Layer 2: 스카웃 최적화 (Scout 루프)
```
무엇을: 세션당 유효 인사이트 수 + 알고리즘 시그널 품질
어떻게: 스캔 속도, 키워드, 좋아요 기준을 자동 조정
피드백: CAPTCHA 발생 여부 + 인사이트 적용 후 스코어
사이클: 하루 1회 (12:00)
에이전트: Kai
```

| 최적화 변수 | 메트릭 | 조정 방법 |
|------------|--------|----------|
| 스와이프 간격 | CAPTCHA 발생률 | 3연속 OK → 속도↑, CAPTCHA → 속도↓ |
| 좋아요 기준 | 시그널 품질 | 10K? 50K? FYP% 변화 추적 |
| 키워드 | 고성과 발견율 | 키워드별 발견된 10K+ 포스트 수 비교 |
| XML vs 스크린샷 비율 | 토큰 비용 | XML 우선, 고성과만 스크린샷 |

### Layer 3: 전략 진화 (메타 루프)
```
무엇을: strategy.md 자체의 품질
어떻게: 실험 아카이브의 ✅/❌ 비율, 스코어 추이
피드백: 수주~수개월 단위의 트렌드
사이클: 자동 (Planner가 매 사이클 판단)
에이전트: Alex (Planner)
```

| 최적화 변수 | 메트릭 | 조정 방법 |
|------------|--------|----------|
| Hook Formulas 순위 | 공식별 평균 스코어 | 데이터 축적 → 순위 재배열 |
| Slide Structure | completion_rate | 새 구조 시도 → 개선 시 흡수 |
| 명화 선정 기준 | 전체 스코어 | 어떤 특성의 명화가 높은 스코어인지 패턴 발견 |
| 폐기 기준 | 하위 스코어 | 일정 스코어 이하 접근법 자동 폐기 |

         └────────────────────┼────────────────────┘
                              │
                              ▼
                    ┌─────────────────┐
                    │  1사이클 1실험    │
                    │  A=대조군        │

### 실험 큐 규칙
- 1사이클 = 1실험 (합치지 않음)
- 순차 실행 (앞 실험 결과 나와야 다음 진행)
- 누적 적용 (✅ 결과는 새 대조군이 됨)
- A = 항상 대조군 (현재 최적 전략)

## 스코어링 체계

### 포스트 스코어 (0-100)
```
Tier 1 (60%) — 배포 확장 핵심
  completion_rate × 0.25    (70% = 만점)
  share_rate × 0.20         (1% = 만점)
  save_rate × 0.15          (2% = 만점)

Tier 2 (30%)
  comment_rate × 0.15       (0.5% = 만점)
  slides_viewed × 0.15      (7/7 = 만점)

Tier 3 (10%)
  like_rate × 0.10          (5% = 만점)
```

### 실험 성공 판정
- 실험 변형(B/C)의 스코어가 대조군(A) 대비 개선 → ✅
- 동일 또는 악화 → ❌
- 표본 부족 (뷰 200 미만) → ⚠️ 추가 검증

### Scout 효율성 지표
```
scan_efficiency = 고성과 발견 수 / 총 스캔 수
token_efficiency = 유효 인사이트 수 / 토큰 사용량
signal_quality = scout 후 포스트의 FYP% 변화
speed_optimality = CAPTCHA 없는 최대 스캔 속도
```

## 자동 조정 메커니즘

### 콘텐츠 (create.py.best)
```
스코어 개선 → create.py 유지 (create.py.best 갱신)
스코어 악화 → create.py.best로 되돌림
```

### Scout (scout_config.json)
```
CAPTCHA 발생 → 간격 +2/+3초, 세션 -5분
3연속 OK → 간격 -1초, 스캔 +5개
키워드별 발견율 → 저성과 키워드 교체
```

### 전략 (strategy.md)
```
실험 ✅ → Hook Formula/Slide Structure 업데이트
실험 ❌ → 해당 접근법 폐기 기록
스코어 추이 하락 → 전면 재검토 트리거
```

## 성공 지표

### 단기 (1주)
- [ ] 자동 사이클이 안정적으로 돌아감 (실패율 <20%)
- [ ] 3개 포스트가 매 사이클 생성+업로드됨
- [ ] 실험 파이프라인 동작 (큐잉 → 실행 → 평가 → 아카이빙)
- [ ] Scout가 CAPTCHA 없이 최적 속도를 찾음

### 중기 (1개월)
- [ ] 평균 스코어가 상승 추세 (experiment_archive.md로 추적)
- [ ] strategy.md가 데이터 기반으로 3회 이상 업데이트됨
- [ ] 최소 1개 [SCOUT] 인사이트가 전략에 흡수됨
- [ ] completion_rate 평균 30%+ (현재 T1이 7%로 최약)

### 장기 (3개월)
- [ ] 포스트 평균 스코어 40+ (현재 best=60.3, 평균 <15)
- [ ] 바이럴 포스트 (10K+ 뷰) 재현 가능한 공식 확립
- [ ] 팔로워 1K+ 달성
- [ ] 실험 ✅ 비율 60%+ (전략 진화가 올바른 방향)
